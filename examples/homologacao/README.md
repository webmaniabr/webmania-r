# Exemplo de homologação

[examples/homologacao/run.sh](run.sh) instala este pacote em uma biblioteca temporária e executa um exemplo opcional que emite, consulta e cancela documentos **somente em homologação** (`ambiente` 2). Sem `WEBMANIA_LIVE=1` ele imprime `{"result":"blocked"}` e sai com 77, sem rede. Configuração somente por variáveis de ambiente: `WEBMANIA_CONSUMER_KEY`, `WEBMANIA_CONSUMER_SECRET`, `WEBMANIA_ACCESS_TOKEN`, `WEBMANIA_ACCESS_TOKEN_SECRET`, `WEBMANIA_ISSUER_TOKEN`, `WEBMANIA_API1_BASE_URL`, `WEBMANIA_FILES_BASE_URL`, `WEBMANIA_API2_BASE_URL`, `WEBMANIA_LIVE_SCOPE` (`readonly`, `nfe`, `nfse` ou `all`), `WEBMANIA_LIVE_NFE_PAYLOAD` e `WEBMANIA_LIVE_NFSE_PAYLOAD` (arquivos JSON com `ambiente` 2), `WEBMANIA_LIVE_LEDGER` (obrigatória nos escopos `nfe`, `nfse` e `all`: arquivo gravável onde cada documento e cada resultado desconhecido ficam registrados; sem ela o exemplo sai com 77 antes de ler credenciais), `WEBMANIA_LIVE_ALLOWED_HOSTS` (obrigatória: hosts separados por vírgula; toda origem configurada precisa estar na lista, e sem ela o exemplo sai com 77 antes de qualquer rede) e, opcionalmente, `WEBMANIA_LIVE_POLL_ATTEMPTS` (de 1 a 20; só reduz o número de consultas de cada espera, e qualquer outro valor sai com 77 antes de qualquer rede). O script cria um diretório temporário próprio dentro de `WEBMANIA_EXAMPLE_WORK` (opcional; padrão `TMPDIR` ou `/tmp`, fora do checkout e sem contê-lo; isso é verificado antes de criar qualquer diretório, então um caminho recusado não deixa nada para trás) e, ao terminar, remove somente esse diretório. A saída é uma linha JSON por passo, com status, resultado e uma referência curta (`sha256` truncado) em vez de identificadores; arquivos aparecem só como tamanho, `sha256` e formato. Credenciais, payloads e bytes nunca são impressos. Uma mutação nunca é reenviada: resultado desconhecido encerra com código 1 e fica no ledger para conciliação por consulta. Enquanto um documento está em processamento, a consulta é repetida com espera crescente (1, 2, 4, 8 e depois 10 segundos), no máximo 20 vezes; depois de um cancelamento isso vale também para `processando_cancelamento` na NFS-e. Só `cancelado` confirma o cancelamento: se o documento continua pendente quando as consultas acabam, ou a consulta falha, o cancelamento fica no ledger com status `unknown` para conciliação por consulta e nunca é reenviado.
